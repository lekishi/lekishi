= RFD 0006 implementation checklist

Implements link:README.adoc[RFD 6: Signed-in drafts on the published site]. The
RFD is in `prediscussion`; nothing below starts before the owner chooses the
gate.

== Decide

- [ ] Owner chooses the gate: A (GitHub sign-in in a Pages Function), B (Cloudflare Access) or C (a separate drafts deployment).
- [ ] Owner authorizes the runtime and secrets the chosen gate needs, and the session cookies, as exceptions to `AGENTS.md`'s static-site rules.
- [ ] Owner answers the open questions: a stale chapter's public URL, previews, session length.

== Build

- [ ] A production build drops unapproved chapters with a warning instead of failing (PR #26).
- [ ] The public `virtual:lekishi-chapters` index lists served chapters only, so no draft title reaches public JavaScript.
- [ ] The drafts tree: `/drafts/chapters/<id>`, `/drafts/data/<id>.json`, `/drafts/chapters.json`, `/drafts/search-index.json`, loaded by `fetch`, never as a chunk.
- [ ] `/drafts/chapters/<id>` of an approved chapter redirects to `/chapters/<id>`.
- [ ] The production draft wording in `release.ts`.
- [ ] Build invariant: no draft id, title or summary outside `/drafts/`; every `/drafts/` file gated by `_routes.json`; a preview build has no drafts tree.

== Gate (option A)

- [ ] GitHub App owned by the `lekishi` organization, Members read-only; owner creates it and sets the Production secrets.
- [ ] `functions/` with `/auth/login`, `/auth/callback`, `/auth/logout` and the `/drafts/*` guard; provider behind one interface.
- [ ] Signed `__Host-lekishi_session` and the `lekishi_member` hint; Vitest coverage for expiry, tampering, non-members and the 404 for anonymous requests.
- [ ] Home cards, search and the 404 page read the drafts tier under the hint.
- [ ] "Sign in" control placed per RFD 5.
- [ ] Verified on production after the owner's go-ahead: anonymous sees no draft, a member sees every draft, previews unchanged.

== Later

- [ ] A second provider (OIDC) behind the same interface.
