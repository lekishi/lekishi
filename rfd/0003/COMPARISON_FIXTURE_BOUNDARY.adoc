= RFD 3 comparison fixture boundary decision

== Provenance and scope

Wave 2's second content item is the bounded Qin comparison fixture, authorized
by the owner on 2026-09-25 ("Approve 1. Proceed with 2"). The fixture is
prepared, source-checked content
(`historical/chapters/qin-conquest-han-233-226/`), and RFD 4 keeps Qin a bounded
comparison fixture rather than a launch chapter: the production atlas must keep
rendering only the Tang chapter while the fixture stays loadable for the later
shared treatment harness. This record is the dated decision that makes both
possible without a second content path: it generalizes the chapter content
boundary and records where the comparison fixture sits in the artifact.

It does not supersede link:CONTENT_BOUNDARY.adoc[the chapter content boundary
decision]. That record's rules for the Tang chapter still hold: one projection,
one browser-safe path into the app, the same refusals (no invented position,
year, or route), and the same build gates. This record changes two things that
record fixed in code: the primary window is now supplied by the caller instead
of being a module constant inside `projection.ts`, and chapters other than the
production chapter load through a catalog that is deliberately not in the
production bundle. CONTENT_BOUNDARY's statement that the owner's editorial
approval was still pending is superseded by the owner's 2026-09-25 approval
recorded in link:../0002/PUBLICATION_APPROVAL.adoc[the publication approval
gate]; the rest of that record remains readable and unchanged.

NOTE: This record's artifact rule — that the fixture's ids must not reach the
release artifact — is **superseded** by
link:COMPARISON_REVIEW_ROUTE.adoc[the comparison review route decision]
(2026-09-25). The owner asked to review the corrected content in the product
before deciding on it, so the fixture now ships as the prerendered review route
`/compare/qin`, which states that it is unapproved preparation, and
`scripts/check-static-build.mjs` requires that page instead of forbidding the
fixture's ids. Everything else here still holds: the caller-supplied coverage
window, the one projection, the catalog as the browser-safe loader for
non-production chapters, the gate over every chapter tree, and the fixture's
`preparation snapshot` status. The measured evidence below records the state as
of this decision and stays readable as what was measured then.

== Decision

* **The projection takes the chapter's coverage model from its caller.**
  `projectChapter` receives a `ChapterCoverage` (the inclusive window the atlas
  opens in, in the astronomical ordinals the contract's normalized endpoints
  use). The production boundary names the Tang chapter's 750–754 window; the
  comparison catalog names the fixture's 233–226 BCE window. No chapter branch
  and no chapter registry lives in the projection, so it stays a pure function
  of documents, sets, and the coverage its caller owns.
* **`src/lib/atlas/chapter-content.ts` keeps binding exactly one chapter
  eagerly**, the reviewed Tang chapter, and stays the only content path the atlas
  route imports. It exports `projectChapterContent`, the throwing boundary, so
  the comparison path crosses the same projection.
* **`src/lib/atlas/chapter-catalog.ts` is the browser-safe loader for
  non-production chapters.** It lazy-loads a chapter's records, sources, and
  publication sets from `historical/chapters/*` and projects them through
  `projectChapterContent` with the caller's coverage. No route imports it, so
  Vite leaves it and its chunks out of the release artifact, and
  `scripts/check-static-build.mjs` fails the build if the fixture's chapter or
  record ids ever reach the artifact. Shipping the comparison harness is
  therefore a deliberate later change rather than an accident.
* **The publication approval gate reads every chapter tree.** `listChapters`
  feeds the gate in `src/lib/historical/contract/publication-approval.test.ts`,
  so a new chapter directory cannot appear with a set the ledger in
  link:../0002/PUBLICATION_APPROVAL.adoc[the publication approval gate] does not
  name. The Tang set carries the owner's approval; the fixture's set is recorded
  as a `preparation snapshot` with the preparing editor's self-review.

== Alternatives considered

* **A hand-written atlas fixture for Qin.** Rejected: it duplicates content the
  contract validates and would drift from it — the same reason CONTENT_BOUNDARY
  rejected a second fixture for Tang.
* **An eager glob over every chapter in the production boundary.** Rejected: it
  would bundle the comparison fixture into the release artifact, shipping
  unreleased preparation content as if it were part of the site.
* **A chapter registry inside `projection.ts`.** Rejected: the coverage model is
  a chapter decision, and a registry would put it in the projection's code
  instead of in the caller that owns the chapter.
* **Rendering the fixture at a second route now.** Rejected: RFD 4 keeps Qin a
  bounded comparison fixture rather than a launch chapter, and the treatment
  comparison does not start before Gate 2.

== Consequences

* The comparison fixture is source-checked, contract-validated content that is
  loadable in a browser through the same projection as the launch chapter,
  without being rendered by the site or shipped in the release artifact.
* Adding another comparison chapter is a content tree plus one catalog call with
  its coverage window, not a new loader and not a change to the production
  boundary.
* The atlas's display labels still print the astronomical year number, which is
  correct for the Tang chapter's CE dates and wrong for a BCE chapter. The
  comparison harness must add BCE formatting before rendering the fixture; this
  record deliberately does not change the production labels.

== Limitations recorded

* The fixture is a preparation snapshot, not owner-approved release content: the
  ledger records it as such and no `owner approved` row exists for it.
* The internal review found source-fidelity and wording corrections in the
  published snapshot (the death dispute's dating and the place of the death
  attributed to the wrong source, a continuous conflict span the sources do not
  state and a 233 BCE dating attributed to the wrong source, the hereditary
  house's 王安五年 equated with the six-states table's 韓王安六年, an officer's
  office held as a continuous 231–230 BCE span between two dated notices, three
  quoted fragments that included or silently dropped the transcription's
  editorial additions, an officer's name attributed to a text-critical
  correction, and a famine notice called a drought). Twelve corrections are
  prepared as unpublished draft revisions, because the publication gate does not
  let the preparing editor supersede a set; publishing a corrected preparation
  set is the owner's decision, the fixture README lists every draft, and the
  fixture's tests pin each reviewed hash.
* The comparison harness is later work. This record makes the fixture loadable
  and keeps it out of the artifact; it does not build the harness, and Gate 2 is
  not satisfied.
* The coverage window is supplied by the caller, so a caller can pass a window
  the content does not fit. The projection fails instead of silently replacing
  it, which the projection suite pins.
