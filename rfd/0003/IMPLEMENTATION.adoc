= RFD 0003 implementation checklist

Implements link:README.adoc[RFD 3: Browser architecture and native options].
The Phoenix scaffold exists; the proposed atlas stack is not implemented.

== Phase 0 — Architecture and rendering evaluation

- [ ] Confirm frontend integration choice and target desktop/touch hardware.
- [ ] Prototype Cesium globe, terrain, routes, picking, and symbolic landmarks.
- [ ] Test labels, geographic scale, local playback, and selection across zoom levels.
- [ ] Compare MapLibre if Cesium fails a specific visual, device, or delivery requirement.
- [ ] Record provider rights, attribution, costs, payload sizes, and measured performance.
- [ ] Resolve the rendering choice without introducing a speculative dual-renderer framework.

== Phase 1 — Browser vertical slice

- [ ] Integrate Svelte/TypeScript and the chosen build tool with Phoenix assets and releases if approved.
- [ ] Implement renderer-independent RFD 2 time/filter/navigation logic and unit tests.
- [ ] Load reviewed content and complete the RFD 1 exploration loop.
- [ ] Verify resource disposal, responsive layout, loading failures, and local scrubbing.
- [ ] Run ExUnit, relevant client tests, browser interactions, and inspected visual checks.

== Phase 2 — Persistent editorial capabilities when needed

- [ ] Define and test local PostgreSQL/PostGIS migrations and bounded geographic/time queries.
- [ ] Establish one content authority and preserve provenance during import.
- [ ] Add permissions and editorial transitions before opening contributor publication.
- [ ] Introduce background jobs or realtime channels only for demonstrated workflows.

== Native feasibility gate — timing and platform remain open

- [ ] Preserve versioned API/data contracts and portable historical behavior fixtures.
- [ ] Compare installable web, native shell, and dedicated native options against actual needs.
- [ ] Test on physical target devices: input, memory, graphics, battery, lifecycle, and accessibility.
- [ ] Review offline data and map caching rights before promising offline support.
- [ ] Record what is shared and what must be rewritten before selecting a native implementation.
